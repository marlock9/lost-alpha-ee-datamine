## Project: S.T.A.L.K.E.R. LAEE mod docs

- Goal: generate `AMMO.md` and `WEAPONS.md`.
- AMMO.md is the source of truth for abs damage + nice ammo names; WEAPONS.md resolves each weapon's ammo from it.
- Parse directly from gamedata ltx files (no mod merge). Only scan files listed in the `#include` directives of `gamedata/config/weapons/weapons.ltx` — any `w_` file NOT included there is not used by the game and must be ignored, which drops the corrupted duplicate `w_saiga êîï.ltx`. Scan tier dirs (t1..t4) AND flat files; do NOT infer tier from the tN directory name.
- One ltx file may contain multiple sections. Base classes (`ammo_base`, `weapon_base`) exist only for inheritance — exclude them; a real ammo type is any section id starting with `ammo_` except the literal `ammo_base`, and a real weapon is any section id starting with `wpn_` except `weapon_base`. Each carries its own `inv_name`; process ALL matching sections, not just the first.
- Tier = ТN prefix (e.g. Т1, Т2, Т3) in the RUSSIAN nice name from the string table (`game/strings/strings_ru.txt`), keyed by `st_<inv_name>`; if a weapon has no Т prefix, fall back to its tN directory. Weapons with no derivable tier (binoculars, mounted gun, knives, addons) are skipped.
- RESOLUTION MECHANISM (authoritative): parse EVERYTHING under `gamedata/config/weapons/` (all `*.ltx`, not just `w_`/`a_`) by following the `#include` graph **transitively** from `weapons.ltx` — this reaches caliber bases (`weapon_<cal>`) and ammo types defined in `ammo/a_*.ltx` (via `ammo/ammo.ltx`), while dropping standalone `w_` files no include references (e.g. corrupted duplicate `w_saiga êîï.ltx`). Ignore the `class = ...` property entirely — inheritance comes ONLY from section headers after the colon (`[id]:parent1,parent2,...`). Those header parents are OTHER SECTIONS, not classes. Follow the full SECTION chain transitively to collect ANY stat (hit_power, rpm, fire_dispersion_base, ammo_mag_size, ammo_class, k_hit, etc.). If a property is missing or blank in a section, it MUST be resolved by walking up the parent chain until the closest ancestor with a non-blank value for that property is found. Caliber bases are real sections (e.g. `weapon_5.45x39`) defined inside `gamedata/config/weapons/ammo/a_*.ltx`, where each ammo type (`ammo_5.45x39_fmj`, …) carries its own `k_hit`/`buck_shot`. So: `wpn_ak74_m1 -> wpn_ak74 -> weapon_5.45x39 -> ammo_class -> [ammo_5.45x39_fmj, …]`. A section may also declare its own `ammo_class` body field (shotguns/grenade launchers). Strip inline `\t;description` comments from header parents before splitting on `,`.
- Nice names: `AMMO.md` "Type" column uses the canonical section id (`ammo_5.45x39_fmj`, underscores); the "Name" comes from the string table keyed by the ammo's `inv_name` (hyphens). `WEAPONS.md` lists each ammo variant using its **SHORT** display name from the string table — look up `inv_name + "_s"` first, fall back to the full `inv_name` name for ammos that have no short variant (e.g. `.500 S&W Magnum`) — and joins variants with `, `.
